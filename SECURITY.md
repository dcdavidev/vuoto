# Security Policy

The Vuoto team takes the security of our developer tools, configurations, and users seriously.

---

## Supported Versions

Only the latest active release receives active security updates and vulnerability patches.

| Version | Supported          |
| :------ | :----------------- |
| `0.1.x` | :white_check_mark: |
| `< 0.1` | :x:                |

---

## Reporting a Vulnerability

If you discover a security vulnerability in any Vuoto package (`vuoto` or `eslint-plugin-vuoto`), please do **not** open a public issue or discussion.

Instead, please report it through one of the following secure channels:

1. **GitHub Private Vulnerability Reporting (Preferred)**:
   Navigate to the [Security Advisories](https://github.com/dcdavidev/vuoto/security/advisories) tab of this repository and click **"Report a vulnerability"**.

2. **Direct Contact**:
   Reach out directly to the maintainers via GitHub profile: [@dcdavidev](https://github.com/dcdavidev).

### What to Include in Your Report

To help us investigate and resolve the issue quickly, please provide as much detail as possible:

- Package name and version affected.
- Description of the vulnerability and its potential impact.
- Step-by-step instructions to reproduce the issue (proof-of-concept code or repository if available).
- Any proposed mitigations or fixes.

---

## Response Process

1. **Acknowledgment**: We will acknowledge receipt of your vulnerability report within **48 hours**.
2. **Investigation**: We will verify the vulnerability, assess its severity, and determine affected packages.
3. **Patch & Advisory**: A patch will be developed, tested, and released as a new version on npm alongside a GitHub Security Advisory.
4. **Credit**: We will gladly credit you in the release notes and security advisory (unless you prefer to remain anonymous).
